# Judging Q&A — the 20 questions and how to answer

Judges pattern-match. Have a one-sentence answer ready for each of these before demo prep ends.

## The universal five

1. **"What problem does this solve?"** — One sentence, one persona, one pain. Not "it's a platform for…".
2. **"Who built what?"** — Answer honestly and specifically; judges probe for the person who did the impressive part.
3. **"What's the hardest technical part?"** — Name the real one. Judges can tell when you say "the UI was tricky" about a CRUD app.
4. **"What did you build vs glue together?"** — Be precise about what's yours and what's a library/API. Credit is fine; vagueness is not.
5. **"What would you do with more time?"** — Pick the one thing that unlocks the next user, not a feature list.

## Investor-type judges

6. "How does this make money / sustain itself?" — Have an answer even if it's "it wouldn't, it's a tool".
7. "What's the market?" — One number, one comparable.
8. "Why hasn't this been built?" — The honest reason is usually "it has, badly" — say that and differentiate.

## Engineer-type judges

9. "What's the architecture?" — One diagram sentence: "X calls Y, Z stores…".
10. "Why this stack?" — "It's what we know" is a valid answer; don't invent justification.
11. "What breaks at scale?" — Name the real bottleneck; shows you understand it.
12. "Any tests / can we see the code?" — Have the repo open, know where the interesting file is.

## Trap questions

13. "Is this just a wrapper around [API]?" — If it is, own it: "the value is in X, the model is commodity".
14. "How is this different from [known product]?" — Have the comparison ready; "we didn't know about it" loses.
15. "What happens when the API is down?" — Have a fallback story, or admit the limitation with a fix.
16. "Did you start before the hackathon?" — Know the pre-existing-code rule cold. Disclose honestly.
17. "Can it do X?" (feature you don't have) — "Not yet — here's how it'd slot in." Never pretend.
18. "Who's the user?" — A specific human or a specific agent, not "developers".
19. "What data does it use?" — Know provenance; judges smell synthetic demo data.
20. "Why did you win?" (asked of past finalists elsewhere) — the meta answer: the demo worked and the scope was honest.

## Rules

- Answer in ≤20 seconds; the follow-up is where you win depth.
- Never say "great question" or restate the question. Judges hear it 40 times.
- If you don't know, say what you'd check. Guessing loses more than honesty.
